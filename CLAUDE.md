# Cable Mouse

Phone + USB cable = mouse for a PC. The phone sends mouse data as USB-MIDI messages (Android "MIDI" USB mode, no root). A small portable PC helper reads the MIDI input and injects cursor/click/scroll events. Full design and phase list: `PLAN.md` (source of truth; update it if the design changes).

## Layout
- `app/` — Android app (Kotlin, Compose, minSdk 23, package `com.cablemouse`)
  - `ui/MainActivity.kt` touchpad, settings and the USB-peripheral MIDI port (device callback, port open/close, send loop); `proto/` MouseProtocol + FrameScheduler; `ui/Onboarding.kt` setup guide; `export/HelperExporter.kt` copies helpers to `Download/CableMouse`
  - `src/main/assets/helpers/` holds the bundled helper binary + README, generated by `make -C helper assets` and committed so the APK builds without MinGW; rerun it whenever helper code changes
- `helper/` — C helper. `common/protocol.[ch]` decoder, `backends/{win,linux,mac}.c`, `main.c`, `tests/`, `Makefile`
- `testvectors/protocol.txt` — wire-protocol test vectors shared by the Kotlin and C tests

## Wire protocol (keep Kotlin and C in sync)
MIDI channel 1, 3-byte messages, all data bytes 7-bit:
- `B0 01 v` dx, `B0 02 v` dy, `B0 03 v` scroll; v = delta + 64 (range -64..63); larger deltas are split into chunks
- `90 n 7F` / `80 n 00` button down/up (0 left, 1 right, 2 middle)
- `B0 7F v` heartbeat / protocol version
Any protocol change must update: `PLAN.md`, `proto/MouseProtocol.kt`, `helper/common/protocol.c`, and `testvectors/protocol.txt`.

## Commands
- Helper host tests: `make -C helper test`
- Windows legacy exe: `make -C helper legacy` (needs `i686-w64-mingw32-gcc`)
- Universal APE: `make -C helper ape` (needs `cosmocc` on PATH)
- Full release (tests + helper + signed APK + checksums into `dist/`): `./scripts/build-release.sh`. The repo has a Gradle wrapper (`./gradlew`); on this machine the system `gradle` (same 9.3.1) avoids a 130 MB download.
- Signed release APK: `gradle :app:assembleRelease` (needs git-ignored `keystore.properties`; the keystore lives in `~/.cablemouse/` and must be backed up, since losing it blocks app updates). Release artifacts are published unversioned as `app-release.apk` and `cablemouse-legacy.exe`.
- Android: `gradle :app:testDebugUnitTest`, `gradle :app:assembleDebug`. Local toolchain: `export JAVA_HOME=~/opt/temurin-21 PATH=~/opt/temurin-21/bin:$PATH`; Android SDK (cmdline-tools, platform 35, build-tools 35.0.0, platform-tools/adb) is in `~/opt/android-sdk`, referenced by the git-ignored `local.properties`. No Compose yet; add it with the UI phase.

## Conventions
- Helper: plain C99, no dependencies beyond the OS; load optional libs with dlopen/LoadLibrary. Backends implement `backend_open/read_midi/move/button/scroll` (see `helper/backend.h`). Protocol decoder is pure (no I/O) so it can be unit tested on the host.
- Helper must release held buttons on disconnect/heartbeat timeout (2 s).
- No root, no admin, no drivers, no installer: don't add features that require them.
- Phase 0 (hardware spikes) needs a real phone and PC; mark steps done in `PLAN.md` only when actually verified on hardware.
